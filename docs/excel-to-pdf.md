# سرویس تبدیل Excel به PDF

قرارداد `IExcelToPdfService` در Application است و پیاده‌سازی `LibreOfficeExcelToPdfService` در Infrastructure قرار دارد. ورودی و خروجی `byte[]` هستند. سرویس به ClosedXML وابسته نیست و فایل اصلی را تغییر نمی‌دهد. خود سرویس عمومی تبدیل API یا رابط کاربری ندارد؛ قابلیت چاپ سند خروج که در ادامه توضیح داده شده، مصرف‌کننده جداگانه آن است.

## چاپ سند خروج کالا

دکمه «چاپ سند خروج» در ستون عملیات لیست خروج کالا، هم در نمای کالا و هم در نمای سند، کل سند مرتبط را چاپ می‌کند. این عملیات به مجوزهای `GoodsIssuesRead` و `GoodsIssuesExport` نیاز دارد. مسیر `GET /endpoint/inventory/goods-issues/{id}/pdf` سند را از دیتابیس می‌خواند و خروجی PDF را با `Cache-Control: no-store` برمی‌گرداند.

قالب اصلی ارائه‌شده در `Warehouse.Infrastructure/Documents/Templates/GoodsIssuePermit.xlsx` به‌صورت EmbeddedResource همراه برنامه منتشر می‌شود. `GoodsIssuePdfService` فقط فیلدهای موجود در فرم را پر می‌کند: شماره، تاریخ شمسی با منطقه زمانی تهران، خارج‌کننده، عنوان کالا، تعداد، واحد، وضعیت/تاریخ عودت و توضیحات همان قلم. کد کالا، شماره اموال، مقصد، مکان ارسال، علت خروج، واحد تحویل‌دهنده و توضیحات کلی سند به ستون‌های فرم اضافه نمی‌شوند. اطلاعات وسیله نقلیه، مسئول انبار، مدیر کارخانه و انتظامات در مدل فعلی موجود نیستند و محل‌های مربوط به آن‌ها برای تکمیل و امضا باقی می‌مانند.

لوگوی گروه‌بندی‌شده و Mergeها حفظ می‌شوند. خروجی این فرم روی A5 عمودی، با حاشیه‌های برابر ۰٫۲ اینچ و وسط‌چین افقی و عمودی تنظیم می‌شود؛ هر برگه به یک صفحه جا داده می‌شود و وابستگی به تنظیمات درایور پرینتر سازنده قالب حذف می‌شود. این تنظیم ویژه گزارش خروج است و رفتار سرویس عمومی تبدیل را تغییر نمی‌دهد. اندازه متن داده‌ها در تمام ردیف‌ها یکسان است. هر برگه ۱۱ ردیف دارد؛ برای اقلام بیشتر یا توضیحات طولانی، برگه‌های بعدی با لوگو و محل امضای همان فرم ساخته می‌شوند. ادامه توضیحات، تعداد کالا را دوباره تکرار نمی‌کند و ردیف‌های بدون کالا خالی می‌مانند. این قالب از فونت **B Nazanin** استفاده می‌کند؛ نصب همین فونت روی سرور برای خروجی نزدیک به قالب ضروری است.

با کلیک روی دکمه چاپ، PDF با توکن کاربر دریافت می‌شود و داخل iframe نامرئی همان صفحه بارگذاری می‌شود. پس از بارگذاری، پنجره استاندارد چاپ مرورگر فراخوانی می‌شود؛ تب جدید، پیش‌نمایش جداگانه یا مودال برنامه باز نمی‌شود. پس از چاپ یا بستن پنجره چاپ، iframe و Blob URL پاک می‌شوند. خروج از صفحه حین آماده‌سازی درخواست را لغو می‌کند. نبودن LibreOffice، timeout یا خطای باز شدن پنجره چاپ با پیام قابل‌فهم نمایش داده می‌شود. برای استفاده واقعی این قابلیت، پیش‌نیازهای LibreOffice و فونت‌های این راهنما باید روی سرور فراهم باشند.

لایه نیمه‌شفاف آماده‌سازی چاپ پس از بازگشت فراخوانی `print()` بسته می‌شود و به دریافت `afterprint` وابسته نیست. این رویداد صرفاً برای پاک‌سازی منابع شنود می‌شود؛ اگر مرورگر آن را نفرستد، منابع پس از پنج دقیقه پاک می‌شوند. مرورگر نتیجه انتخاب چاپ، ذخیره PDF یا لغو را به صفحه گزارش نمی‌دهد؛ بنابراین پیام موفقیت یا لغو نمایش داده نمی‌شود. در Firefox دسترسی به رویدادهای iframe ممکن است محدود باشد؛ فراخوانی چاپ مستقل از این دسترسی انجام می‌شود و رویداد روی پنجره اصلی نیز شنود می‌شود.

```csharp
using Warehouse.Application.Common.Interfaces;

public sealed class ReportService(IExcelToPdfService excelToPdfService)
{
    public Task<byte[]> GeneratePdfAsync(byte[] excelBytes, CancellationToken cancellationToken = default) =>
        excelToPdfService.ConvertAsync(excelBytes, cancellationToken);
}
```

برای خروجی ClosedXML، Workbook را در MemoryStream ذخیره کنید و `stream.ToArray()` را به همین متد بدهید. تا پایان فراخوانی بایت‌های ورودی را از نخ دیگری تغییر ندهید. سرویس پس از دریافت نوبت یک کپی مستقل برای اعتبارسنجی و تبدیل می‌سازد.

## نصب روی Windows Server و IIS

1. نسخه پشتیبانی‌شده و به‌روز LibreOffice را از [سایت رسمی](https://www.libreoffice.org/download/download-libreoffice/) روی سرور نصب کنید. Microsoft Office، Excel و Office Interop نیاز نیستند. نصب و تنظیمات سیستم باید توسط مدیر سرور انجام شوند؛ سرویس برنامه نصب‌کننده اجرا نمی‌کند.
2. وجود `C:\Program Files\LibreOffice\program\soffice.com` و `soffice.bin` را بررسی کنید. با وجود اینکه تنظیم پیش‌فرض `soffice.exe` است، سرویس روی Windows به‌طور خودکار همتای `.com` را اجرا می‌کند تا انتظار برای پردازش و خواندن خروجی کنسول قابل اتکا باشد. اگر `.com` موجود نباشد، خطای نصب برمی‌گردد. این انتخاب مطابق [راهنمای رسمی اجرای خط فرمان](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html) است.
3. فونت‌های استفاده‌شده در گزارش، مانند Tahoma و فونت‌های فارسی سازمان، را برای همه کاربران سرور نصب کنید و App Pool را پس از نصب فونت‌ها recycle کنید. نصب فونت فقط برای کاربر مدیر کافی نیست. حساب سرویس باید اجازه خواندن فونت‌ها را داشته باشد. نبود فونت می‌تواند جایگزینی فونت، تغییر اندازه متن و اختلاف صفحه‌بندی ایجاد کند.
4. یک مسیر محلی اختصاصی مانند `D:\WarehouseTemp\ExcelToPdf` بسازید. در `LibreOffice:TempRootPath` این مسیر را تنظیم کنید. هویت App Pool مانند `IIS AppPool\Warehouse` باید در این مسیر مجوز Modify، شامل ساختن و حذف فایل و پوشه، داشته باشد. دسترسی را فقط به هویت سرویس و مدیران بدهید. این مسیر نباید زیر `wwwroot`، یک share شبکه یا junction/symlink باشد. مسیر پیش‌فرض در پوشه موقت حساب جاری، زیر `Warehouse\ExcelToPdf` است.
5. به هویت App Pool فقط Read & Execute روی فایل‌های نصب LibreOffice بدهید. اجرای Administrator، فعال کردن تعامل با Desktop و نصب Microsoft Excel ضروری نیست. `Load User Profile` را در App Pool فعال کنید تا وابستگی‌های سیستم و فونت‌های حساب به‌درستی در دسترس باشند؛ LibreOffice همچنان برای هر تبدیل پروفایل مستقل خودش را می‌گیرد.
6. با همان هویت App Pool یک گزارش نمونه را آزمایش کنید. مسیر معتبر روی رایانه توسعه به معنای دسترسی حساب IIS روی سرور نیست. خطاهای دسترسی، نبود فایل اجرایی و نبود PDF به‌صورت خطای معنادار برگردانده می‌شوند.

## تنظیمات

بخش `LibreOffice` در `Warehouse.Server/appsettings.json` ثبت شده است. برای استقرار می‌توان مقادیر را با Configuration معمول پروژه، از جمله متغیرهای محیطی مانند `LibreOffice__ExecutablePath` و `LibreOffice__TempRootPath`، جایگزین کرد.

| تنظیم | پیش‌فرض | کاربرد |
|---|---:|---|
| ExecutablePath | `C:\Program Files\LibreOffice\program\soffice.exe` | مسیر مطلق فایل اجرایی؛ روی Windows همتای `.com` انتخاب می‌شود |
| TempRootPath | مسیر Temp حساب جاری + `Warehouse\ExcelToPdf` | ریشه اختصاصی فایل‌های موقت؛ باید مطلق باشد |
| TimeoutSeconds | 90 | مهلت هر تبدیل، پس از دریافت نوبت؛ ۱ تا ۳۶۰۰ ثانیه |
| MaxConcurrentConversions | 2 | تعداد تبدیل‌های هم‌زمان در یک process؛ ۱ تا ۱۶ |
| MaxInputSizeMegabytes | 50 | سقف بایت‌های Excel ورودی |
| MaxOutputSizeMegabytes | 100 | سقف بایت‌های PDF خروجی |
| MaxUncompressedSizeMegabytes | 256 | سقف مجموع اندازه بازشده اجزای XLSX |
| MaxArchiveEntries | 10000 | سقف تعداد اجزای ZIP |
| MaxCompressionRatio | 1000 | سقف نسبت اندازه بازشده به فشرده هر جزء |
| StaleDirectoryAgeHours | 24 | سن پوشه‌های باقی‌مانده قابل پاک‌سازی |

تنظیمات در شروع برنامه اعتبارسنجی می‌شوند. وجود فایل اجرایی هنگام تبدیل بررسی می‌شود تا نصب نبودن LibreOffice مانع کار بخش‌های دیگر برنامه نشود. برای اعمال تنظیمات، برنامه را restart کنید؛ `IOptionsMonitor` و تغییر لحظه‌ای ظرفیت Semaphore استفاده نشده است.

سرویس Singleton است و Semaphore مشترک بین همه scopeها دارد. انتظار در صف با CancellationToken لغو می‌شود. مهلت ۹۰ ثانیه از زمان گرفتن نوبت شروع می‌شود و اعتبارسنجی، عملیات فایل و اجرای تبدیل را پوشش می‌دهد. پس از انقضای مهلت، خاتمه دادن به پردازش و پاک‌سازی ممکن است چند ثانیه بیشتر زمان ببرد. برای درخواست HTTP، CancellationToken درخواست را تا Handler و سرویس منتقل کنید.

محدودیت هم‌زمانی در سطح یک process است. اگر IIS web garden، چند سرور یا چند replica دارید، ظرفیت کل حاصل جمع ظرفیت workerها است؛ برای سقف سراسری به صف یا worker مرکزی نیاز دارید. این سرویس صف توزیع‌شده ایجاد نمی‌کند.

## حفظ چاپ، فارسی و کیفیت

تبدیل با فیلتر `calc_pdf_Export` انجام می‌شود. سرویس تنظیمات A4/A3، Landscape، Print Area، Scaling، Page Break، Header/Footer، عرض ستون‌ها، ارتفاع ردیف‌ها و استایل‌ها را بازنویسی نمی‌کند و تبدیل را به یک صفحه اجبار نمی‌کند. تمام شیت‌های قابل چاپ مطابق رفتار Calc به PDF صادر می‌شوند. شیت‌های مخفی، محدوده‌های چاپ و محدوده‌های خالی مطابق تنظیمات سند و رفتار LibreOffice تفسیر می‌شوند.

متن‌ها به تصویر تبدیل نمی‌شوند و خروجی PDF معمولاً دارای متن قابل انتخاب و جست‌وجو است. اتصال حروف فارسی، جهت متن، RTL و اندازه‌بندی باید با فونت‌های واقعی سازمان روی سرور بررسی شوند. اختلاف موتور Excel و Calc، فونت جایگزین، نمودارهای خاص و فرمول‌های ناسازگار می‌تواند نتیجه را تغییر دهد؛ تطابق صددرصدی با Print to PDF اکسل تضمین نمی‌شود.

## امنیت ورودی و محدودیت‌ها

- XLSX با امضای ZIP، فهرست اجزا، content type واقعی Workbook و XMLهای بدون DTD/XXE بررسی می‌شود. اندازه ورودی، اندازه بازشده، تعداد اجزا و نسبت فشرده‌سازی محدود است. خواندن هر جزء هم به طول اعلام‌شده آن محدود می‌شود.
- XLS بر اساس امضای OLE، مشخصات header، زنجیره DIFAT/FAT و وجود stream به نام Workbook یا Book تشخیص داده می‌شود. بررسی نهایی BIFF و امکان چاپ به عهده فیلتر صریح `MS Excel 97` در LibreOffice است. وجود header به‌تنهایی اثبات سالم بودن سلول‌ها نیست. XLS مبتنی بر XML قدیمی، CSV، XLSB، XLSM و فایل‌های رمزگذاری‌شده پشتیبانی نمی‌شوند.
- XLSXهای دارای external workbook link، data connection، تصویر/فایل خارجی در relationship، ماکرو یا فرمول‌های شبکه‌ای شناخته‌شده مثل WEBSERVICE، IMAGE، RTD و DDE رد می‌شوند. تصاویر جاسازی‌شده داخل Workbook باقی می‌مانند. hyperlink معمولی مجاز است و هنگام تبدیل نباید باز شود.
- در پروفایل هر درخواست `DisableMacrosExecution=true`، `DisableActiveContent=true` و سطح امنیت ماکرو ۳ فعال است؛ منابع مورد اعتماد کاربر از پروفایل شخصی کپی نمی‌شوند. به‌روزرسانی لینک‌های Calc روی «هرگز» قرار دارد. تنظیمات امنیتی بر اساس [schema رسمی Common](https://github.com/LibreOffice/core/blob/master/officecfg/registry/schema/org/openoffice/Office/Common.xcs) و [schema رسمی Calc](https://github.com/LibreOffice/core/blob/master/officecfg/registry/schema/org/openoffice/Office/Calc.xcs) هستند.
- این بررسی‌ها sandbox سیستم‌عامل نیستند و برای XLS قدیمی تحلیل کامل لینک‌ها یا فرمول‌ها انجام نمی‌شود. برای تضمین عدم دریافت منابع خارجی، اجرای LibreOffice را با سیاست سیستم‌عامل/شبکه بدون دسترسی خروجی به شبکه و بدون دسترسی به فایل‌های حساس محدود کنید. در Windows، قوانین خروجی باید `soffice.bin` را هم پوشش دهند؛ محدود کردن فقط `soffice.exe` کافی نیست. فایل‌های شبکه‌ای و فرمول‌های خارجی در چنین محیطی ممکن است با مقدار cacheشده یا خطا چاپ شوند.
- سرویس از Shell استفاده نمی‌کند و تمام آرگومان‌ها با `ArgumentList` ارسال می‌شوند. فایل ورودی تحت نام ثابت کنترل‌شده، داخل پوشه GUID اختصاصی قرار می‌گیرد. نام یا مسیر فایل از مصرف‌کننده پذیرفته نمی‌شود.
- سقف فایل، سقف بازشدن ZIP، timeout و concurrency مصرف منابع را محدود می‌کنند، اما سقف سخت حافظه/CPU یک پردازش LibreOffice نیستند. برای فایل واقعاً غیرقابل اعتماد، اجرای worker تحت Windows Job Object یا محیط ایزوله با سهمیه حافظه/CPU و حساب اختصاصی بدون دسترسی به secrets برنامه توصیه می‌شود. این سرویس مجوز سیستمی یا قواعد firewall را خودکار تغییر نمی‌دهد. LibreOffice را با آخرین اصلاحات امنیتی نگه دارید.

## Timeout، خطا و پاک‌سازی

| وضعیت | نتیجه |
|---|---|
| ورودی null | `ArgumentNullException` |
| ورودی خالی | `ArgumentException` |
| فرمت نامعتبر، خرابی، محدودیت اندازه، نصب نبودن LibreOffice یا شکست تبدیل | `ExcelToPdfConversionException` |
| انقضای مهلت | `TimeoutException` |
| لغو توسط فراخواننده | `OperationCanceledException` با توکن فراخواننده |

stdout و stderr به‌صورت هم‌زمان و با buffer محدود تخلیه می‌شوند تا deadlock و انباشته شدن خروجی در حافظه رخ ندهد. محتوای آن‌ها، سلول‌ها، نام‌های فایل اصلی و پیام parser که ممکن است داده سند داشته باشد در log ثبت نمی‌شوند. شناسه تبدیل، مدت، کد خروج و نوع خطای فایل‌سیستم ثبت می‌شوند.

در timeout یا cancellation درخت پردازش خاتمه داده می‌شود. اگر سیستم‌عامل اجازه پایان پردازش را ندهد، خطای Critical با PID ثبت می‌شود تا اپراتور بررسی کند. پاک‌سازی در finally با سه تلاش انجام می‌شود؛ شکست پاک‌سازی خطای اصلی را مخفی نمی‌کند و Semaphore آزاد می‌شود.

ساختار پوشه هر کار:

```text
ExcelToPdf/{GUID}/
  .lease
  input.xlsx یا input.xls
  input.pdf
  profile/user/registrymodifications.xcu
  temp/
```

یک BackgroundService در شروع برنامه و سپس هر ساعت پوشه‌های GUID قدیمی را پاک می‌کند. lease انحصاری مانع حذف کار فعال، حتی در worker دیگر IIS، می‌شود. پوشه ناقص بدون lease که از ساخت آن بیش از زمان تعیین‌شده گذشته هم پاک می‌شود. پوشه‌های تازه، نام‌های غیر GUID و junction/symlink ریشه یا پوشه کار حذف نمی‌شوند. ریشه Temp باید منحصراً برای این سرویس باشد.

اگر برنامه خاموش بماند، پاک‌سازی داخل برنامه هم اجرا نمی‌شود؛ برای این حالت نگه‌داری سرور باید پوشه‌های قدیمی همین ریشه اختصاصی را در زمان توقف workerها بررسی کند. crash سیستم یا terminate اجباری ممکن است پردازش یتیم باقی بگذارد؛ پایش PIDهای LibreOffice و quota سیستم‌عامل برای این وضعیت لازم است. فایل‌های باقی‌مانده تا زمان حذف ممکن است حاوی داده گزارش باشند، پس ACL ریشه موقت اهمیت دارد.

## تست و پذیرش روی سرور

تست‌های مستقل به نصب LibreOffice وابسته نیستند:

```powershell
dotnet test Warehouse.Infrastructure.Tests/Warehouse.Infrastructure.Tests.csproj --filter 'Category!=LibreOfficeIntegration'
```

تست‌های واقعی به‌صورت پیش‌فرض Skip می‌شوند. بعد از نصب LibreOffice:

```powershell
$env:EXCEL_TO_PDF_LIBREOFFICE_PATH = 'C:\Program Files\LibreOffice\program\soffice.com'
dotnet test Warehouse.Infrastructure.Tests/Warehouse.Infrastructure.Tests.csproj --filter 'Category=LibreOfficeIntegration'
```

سناریوهای واقعی شامل XLSX ساده، فارسی/RTL، Merge، رنگ و Border، A4، Landscape، چند شیت، چند صفحه، Print Area و XLS قدیمی هستند. XLS واقعی ابتدا از fixture مورد اعتماد توسط LibreOffice ساخته و سپس به سرویس داده می‌شود. تست‌های مستقل حفظ بایت‌های ورودی، ورودی خراب، DTD و لینک خارجی، سقف منابع، هم‌زمانی، لغو صف، timeout، شکست پردازش، خروجی نامعتبر و پاک‌سازی را پوشش می‌دهند. تست اجرای Process همچنین خروجی حجیم دو pipe و خاتمه دادن به فرزند پردازش را بررسی می‌کند.

موفقیت smoke test اثبات تشابه بصری نیست. در پذیرش استقرار، چند گزارش واقعی سازمان با فونت‌های نصب‌شده را به PDF تبدیل کنید و صفحات را با نسخه چاپ‌شده Excel مقایسه کنید: اتصال حروف فارسی، RTL، اعداد، عرض ستون‌ها، سرصفحه/پاصفحه، لوگو، Merge، شکست صفحات و Print Area. متن فارسی را در PDF جست‌وجو و کپی کنید. تا انجام این بررسی روی سرور هدف، کیفیت بصری واقعی تأییدشده محسوب نمی‌شود.
